# web-freshness — 変わりやすい情報は Web で最新を確認してから答える

モデルの知識にはカットオフがあり、セッション開始時に渡される「今日の日付」との差は数か月以上になりうる。
変わりやすい情報を記憶だけで断定しない。

## 回答前に Web 検索（WebSearch / WebFetch）で確認する対象

- AI 製品・サービスの機能や提供状況（ChatGPT / Claude / Gemini / Copilot など。Computer Use、エージェント、新モデル）
- ソフトウェア・ライブラリ・ツールのバージョン、リリース、廃止・非推奨、破壊的変更
- API 仕様、料金、無料枠、利用制限、対応 OS
- ニュース、イベント、日程、締切、組織や人物の現状
- 「最新」「今」「現在」「最近」「比較」を含む質問
- 自分の知識の時点（カットオフ）より後に変わった可能性がある事柄全般

## 今日の日付

- 毎ターン、UserPromptSubmit hook（claude-dotfiles の `scripts/now-context.mjs`）が「現在日時」を文脈に入れる。日付はセッション開始時の値ではなく、こちらを基準にする。
- 現在日時と自分の知識の時点を比べ、差が大きいほど「知らない変化がある」前提で確認する。

## ライブラリ・API のドキュメントは Context7 を優先

- ライブラリやフレームワークの API、使い方、設定手順、コード生成では、記憶で書かず Context7 MCP（`resolve-library-id` → `query-docs`）で最新の公式ドキュメントを引く。プロジェクトで使っているバージョンが分かればそれに合わせる。
- 無料枠には月あたりの呼び出し上限がある。1つの質問につき必要なライブラリだけ引き、同じ内容を何度も引き直さない。
- Context7 が使えない、または該当ライブラリが無いときは、公式ドキュメントを WebSearch / WebFetch で確認する。

## やり方

- 迷ったら確認する。検索のコストより、古い情報で断定するコストのほうが高い。
- まず `mode: "standard"` で検索し、結果が薄い・古い・的外れなときだけ `extended` を使う。
- 一次情報（公式ドキュメント、公式ブログ、リリースノート）を優先し、回答に出典 URL と、その情報がいつ時点のものかを付ける。
- 検索できなかった、または確認しきれなかった場合は「◯年◯月時点の知識による」と明記し、未確認であることを伝える。

## 確認しなくてよいもの

- 普遍的な知識（アルゴリズム、数学、言語仕様の基本、競プロの解法など）
- 手元のコードやファイルを見れば分かること（Web ではなくローカルを確認する）
- 雑談や意見を求める質問
